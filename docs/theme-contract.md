# Theme Contract

## 原则

主题是 presentation-only layer。它可以重新安排布局，但不能改变请求协议、模型判断、账号调度、计费、权限、审批语义或附件生命周期。

### 可以改

- CSS 颜色、字体、字号、字重、行高、间距、边框、圆角、阴影
- 侧栏和面板的排列方式
- 按钮的图标/文字组合，只要命令仍有可见的 accessible name
- 进度条、思考滑块、命令折叠区和图片等待态的视觉表达
- 主题切换、面板出现、消息出现的动画

### 不可以改

- 删除或伪造模型、分组、工具、文件、命令或审批状态
- 把真实回答、代码、公式、引用、错误文本变成装饰图片
- 用主题判断用户权限或决定是否发送请求
- 在 reduced-motion 或低性能设备上阻断操作
- 让文本、按钮、滑块、附件或命令结果互相覆盖

## 组件矩阵

| Surface | 必须可见的状态 | 必须可用的交互 |
| --- | --- | --- |
| Chat shell | 当前主题、浅深色、连接/保存状态 | 打开历史、设置、分组、模型、Work、文件 |
| Composer | 草稿、附件、模型、思考强度、发送/停止 | 添加/删除附件、发送、取消、重试、编辑 |
| Assistant message | 回复正文、真实思考摘要、来源/引用、工具结果、错误 | 展开/折叠、复制、下载、重试、继续回答 |
| Image workbench | 原图/结果、模型、等待进度、失败与重试 | 选择图片模型、上传/改图、保存/下载、取消 |
| Settings | 主题、浅深色、账户、API/下载入口 | 主题切换、模式切换、保存、返回 |
| Work project | 文件、计划、命令、结果、审批、终端、恢复状态 | 进入项目、发送任务、展开每条命令、允许/拒绝、重试/继续 |
| Narrow/mobile | 核心按钮和文字不截断 | 侧栏、面板、选择器和输入框仍可操作 |

## Work 项目页的最小结构

项目入口不能只显示一个“工程模式”开关。主题必须给以下信息留下稳定的视觉位置：

1. 项目名和当前目录/保存状态。
2. 文件入口和当前选中文件。
3. 对话任务和真实模型/推理强度。
4. 计划步骤及其完成状态。
5. 每条命令单独的折叠区，显示命令、工作目录、退出码和完整结果。
6. 审批区，明确是逐条审批还是免审批，并显示当前状态。
7. 终端输出、编译结果、SSH 结果和错误。
8. 自动重试、检查点、继续任务和取消操作。
9. 项目输入框和附件入口。

主题可以把这些内容做成三栏、上下分栏或移动端抽屉，但不应把它们藏到无法发现的假按钮里。

## 切换动画

`src/theme-transition.js` 使用 GSAP 创建短时粒子散开层：

- 动画层只覆盖视觉，不阻挡操作，也不改变页面数据。
- 切换中只创建和销毁自己拥有的 timeline、DOM 节点和计时器。
- `prefers-reduced-motion: reduce` 直接执行切换。
- 低内存、低核心数和 `saveData` 设备使用较少粒子和更短时长。
- 页面进入后台时应结束动画，避免后台持续占用 CPU。
- 任何异常都应回退到无动画切换，不能卡住主题按钮。

## 宿主接入

真实 Chat 宿主使用 `runtime/production/` 中的扩展资源。推荐顺序：

1. 先加载 `kuan-html-to-image.js`，它提供可选的 DOM 快照能力。
2. 再以 module 方式加载 `kuan-chat-theme-v2.js`。
3. 保证同目录存在 `kuan-tc1003-e92a67dc3f.js`、`kuan-punctuation-knot.js`、`kuan-theme-transition.js`。
4. 加载对应 CSS：主题、标点图案、Work 项目显示。
5. 在宿主挂载后保留 `.kuan-chat-shell`、`data-kuan-group-platform`、`.kuan-settings` 和 Work 事件节点。

这些资源只扩展显示层，不替换 Sub2API 核心或官方前端。
